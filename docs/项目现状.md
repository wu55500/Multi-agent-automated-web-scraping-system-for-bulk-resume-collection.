## 1. 项目是什么

"对证下药"（dz）：深圳龙岗区数据方向求职用的个人工具。抓招聘 JD → 挖技能要求（证据链）→ 分类（城市/公司规模/Agent 等级/岗位家族）→ 差距分析 → 项目规划 → 简历措辞 → 投递队列。**提交动作永远由人点，工具只整理不代投。**

## 3. 已冻结的架构决策（不许翻案，除非用户重新裁决）

1. 三 Agent：Agent1 求职执行 / Agent2 沟通面试 / Agent3 独立审计；写操作必须过独立审计闸门
2. 五库物理隔离用表名前缀区分（gov_/mi_/a1_/a2_/a3_），数仓用 dw_ods/dw_dwd/dw_dws/dw_ads
3. 岗位三身份：source_posting_id / canonical_job_id / job_version_id；JD 历史版本永不覆盖
4. 技能证据链：skill → requirement_level + evidence_text + evidence_location + extractor_version
5. 引擎：SQLite = 当前运行载体（手机无服务器）；PostgreSQL = 设计基线（DDL/方言/RLS 按 PG 写）；store 层为唯一 DB 访问层；阶段 1 用 迁移PG脚本.sql 切换，业务代码零改动
6. 多租户：tenant_id 第一天建（设计基线日增十万级 JD、千级租户；实现分三层：手机单租户 → 阶段 1 单机 PG → K8s 按触发条件）
7. 预算：200-800 元/月档，**800 为顶额**（用户确认）；成本大头在运维底座+模型 API，不在数据（锚点：同类项目 $25/月）
8. 目标市场：海内外双轨（海外 ATS 直采=技术栈趋势参照；国内=真实战场，官方渠道/授权/商务合作）

## 4. 合规红线（不可逾越）

- 不绕验证码、不逆向签名、不做指纹伪装、不用代理池、不无头自动提交（刑法 285 条二/三款）
- 采集只走：官方 API/RSS/sitemap（L1）→ 限速公开页（L2）→ 公开 JSON（L3）→ 人工辅助（L4）
- 遵守 robots.txt 与 crawl-delay；按公司分批、批内串行
- "受限对抗模块"明确不建（连接口位都不留），改为"受限源接入协议"（授权 token / robots 校验 / 商务密钥）
